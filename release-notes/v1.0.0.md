# Modbus Master 1.0.0 (beta)

> **This is a beta.** It is complete enough to use on real equipment, but it has not yet been through a season
> of daily work. Expect bugs. **If you hit one, please report it** — what you did, what happened, and what you
> expected. The traffic list exports as CSV or pcap, and that usually settles the question on its own.

A Modbus master for **RTU, ASCII, TCP, UDP, RTU over TCP** and **Modbus/TCP Security (TLS)**: polling windows
with names, scale and alarm limits, writing with confirmation, a slave address scanner, an IP network scanner,
serial parameter detection, a register map for undocumented devices, an RS-485 sniffer with pcap export, a
slave simulator, device templates, trends and charts, MQTT and InfluxDB publishing — and `mmcli`, the same
engine on the command line, including scripted commissioning with `expect` checks.

| Download | For |
|---|---|
| `ModbusMaster-1.0.0-x64.msi` | install for all users: Start menu shortcut, firewall rule for TCP 502, `mmcli` on `PATH` |
| `ModbusMaster-1.0.0-x64-portable.zip` | unpack and run; all data stays in a `Data` folder beside the program |

Windows x64. The .NET runtime is included, nothing else has to be installed.

**Writing to a device.** Every write is confirmed first, with the register words shown in hex before they are
sent, and recorded in `audit.log`. A **read-only mode** refuses every write at the transport — worth switching
on before you connect to an installation you are only allowed to look at. Input registers and discrete inputs
are read-only, and a write to one is refused with a reason before a frame is sent.

The packages are not digitally signed, so SmartScreen warns about an unknown publisher.

The interface is Polish, English or German, and so is `mmcli`, including its help.

## Known limits of this build

- The sniffer needs a port that can hear the line: an RS-485 adapter in listen-only mode, or a tap.
- Modbus has no discovery, so finding devices means asking one address after another. Ranges are capped so a
  typo cannot sweep a whole network.
- TLS has been tested against a self-signed server with a pinned thumbprint; certificates from a company CA
  have not been tried.
